# 评审通过只看完成程度，派审带上审阅范围

不划范围时，步骤确定会被要求补架构、接口或代码骨架。不分级时，必须改的和可以后补的要等一句「已达到预期」才定稿。

因此每次派审带上该环节的审阅范围。步骤确定只审大体步骤。执行中的新决策点只审这条岔路和尚未验证的步骤。已交接后只审尚未开始的步骤。

范围内意见分 P0、P1、P2。P0 与 P1 必须解决；本轮有它们时完成程度取中或低，写入后再审。只剩 P2 时写入方案，完成程度为高则评审收敛。评审阶段是否通过只看完成程度是否为高。

非常确信对照已有知识、已有方案、公开方案也无法把完成程度做到高时，停在「审阅不通过」。只剩 P2、或完成程度为中或低，本身不是这个结论。

这取代 [0028](0028-review-loop-until-expected-or-honest-stop.md) 里「改进意见为已达到预期才开工」的那一条。低或中仍进入完善、完善期间不改代码，仍然有效。

## Considered Options

- 继续用「已达到预期」当开工门。审阅者没有被限定范围，步骤阶段仍会被拉去要详细设计。
- 只有 P0 必须解决，P1 可随完成程度为高一起收敛。P1 仍是方案做不稳的缺口，和 P0 一样挡住「高」。
- 完成程度为高就开工，P0 另说。高和未解决的 P0 同时出现时，会把还要改的方案拿去实现。
