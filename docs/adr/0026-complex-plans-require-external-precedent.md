# 复杂档定稿前必须做一次外部参照

复杂档若只看本仓就定步骤，会把没对照过公开做法的方案交出去。task-wizard 与 task-explore 因此只在复杂档、定稿前做一次外部参照：检索公开资料，最多读两处公开原文，只追最会影响步骤的一个做法。对上原文的记为事实，对不上的记为假设，方案照常写完。两处做法相反时两条都留作事实，选哪条是决策点。简单和中等不离开本仓。Goal 里会改步骤的假设仍走「理解不够」，不新设退出点。explore 里的假设保持为假设；同一问题且出处仍对得上则不重查。chat 不查。

## Considered Options

- 中等也查，或每档都查。简单任务会被检索拖住，也和「拿不准往简单靠」冲突。
- 觉得本仓已经够就可以跳过。复杂档就会回到闭门造车。
- 两处出处矛盾就都降为假设。已经对上原文的公开做法不该因为彼此不同就变成没查到。
- 正文点名具体 MCP。换一台机器就停，共享 skill 只写检索公开资料和读公开仓库的能力。
