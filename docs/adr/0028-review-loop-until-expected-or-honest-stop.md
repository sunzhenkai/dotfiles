# 审阅循环直到达到预期，或诚实说明到不了

开工门「已达到预期」由 [0029](0029-review-scope-and-completion-level.md) 取代为：完成程度为高，且本轮没有 P0、P1，P2 已写入。低或中进入完善、完善期间不改代码，仍然有效。

只给定级时，执行者不知道改哪一句。同一缺口再出现，也常常还能从已有知识、已有方案或公开方案里找到下一条改法。因此循环是：出方案 → 评审（定级 + 改进意见）→ 修改方案 → 再评审。定级不单独结束循环。改进意见写清改哪一条完成判据或步骤，并指回来源。改进意见为「已达到预期」才开工。

非常确信这三处都无法再进一步完善以达到预期时，停在「审阅不通过」，写明预期以及为什么补不上。定级为低或中、同一缺口还在，本身不是这个结论。给出结论之前要已经对照过这三处。简单和中等不把每一轮都做成外部参照；缺口可能被公开做法补上时，先对照再下结论。

这取代 [0027](0027-low-medium-review-continues-refinement.md) 里「同一缺陷再审仍在就停」的那一条。低或中不因此退出、完善期间不改代码，仍然有效。

## Considered Options

- 同一缺陷再出现就停。缺口还在时，往往还有下一条改法，停下来会再次把完善做成退出。
- 定级为高就开工，改进意见另说。定级和改法不一致时，会把还要改的方案拿去实现。
- 每一轮都检索公开方案。简单任务会被检索拖住，也和复杂档才做外部参照冲突。
