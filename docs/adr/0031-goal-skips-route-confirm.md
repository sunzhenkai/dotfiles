# Goal 收敛后按档位直接下一跳

评审已经收敛时，再问「走 task-explore」还是「仍按此方案执行」不增加信息，还会把后一句误用成在本会话实施复杂档步骤。

因此处在 goal 里时减少确认：简单、中等、复杂三档在评审收敛后直接进入对应下一跳，不索取路由确认，不列二选一。复杂档改为 `已交接` 并当轮开始 task-explore，不改业务代码。单独「继续」只对退出点造成的 `已停` 无效。排查写不出步骤、详细设计，以及危险操作、线上动作、泄密等退出点仍停。执行中升档停止改代码，改为 `已交接` 并按新档位衔接。

task-explore 自己的创建目录、选阶段、确认冻结仍由该 skill 执行。wizard 不把这些门禁收成收敛后的选项。

这取代 [0025](0025-goal-reviewer-binds-on-high-confidence.md) 里「复杂档仍等用户说走 task-explore」的那一条。

## Considered Options

- 收敛后仍停着等用户点名路由。方案已经审过，这一等只是再确认一次。
- 把「仍按此方案执行」留成可以在本会话按步骤改代码的出口。复杂档会绕开 task-explore。
- 一并改掉 task-explore 里的创建目录、选阶段、冻结确认。两份契约会缠在一起，留在该 skill。
