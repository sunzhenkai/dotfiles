# 结构化工作流可调用角色化评审

role-based-reviewer 的默认门禁防止普通「帮我 review」自动展开多角色。但分阶段交付工作流（如复杂 Goal 的方案门）需要在固定决策点传入完整审阅边界和固定角色集。门 1 因此承认一种窄例外：调用方以结构化参数传入 `mode=review`、完整合法 `roles=`，以及完成判据、质量画像 / 角色底线、显式降级、审与不审范围等边界输入。此时按传入角色执行；传入完整 `roles=` 属已指定，不增删、不因超过两个角色反问。只说“进入评审环节”而缺结构化角色集或边界输入，仍不算触发。

## Considered Options

- 只认用户当轮点名。工作流的固定质量门会被误判为自动加载，实现回到单一视角。
- 放宽普通 review 的自动推断。会把“帮我看看”扩大成多角色评审，违反发现克制。
- 让 task-wizard 自己扮演三个角色。执行者自审不独立，产品 / 设计 / 工程盲区难以暴露。

## Consequence

role-based-reviewer 保持只读和误触防护；工作流调用必须提供可检查边界。缺边界输入时按已有判据审查并声明缺口，不擅自扩大范围。
