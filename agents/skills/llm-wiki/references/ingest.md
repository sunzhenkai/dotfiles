# 摄入

把一份本地材料编译进 wiki。一次 ingest 通常会动多页：源摘要 + 若干实体/概念 + 交叉引用。

## 输入

优先顺序：用户指定的本地文件 → 粘贴文本 → 当前对话中要保留的结论。

不要主动去抓任意 URL。用户明确给出链接并要求纳入时，先确认范围再取回文本。

大文件按章节或自然段分块，每块仍绑定同一来源。

## 步骤

1. **读材料**，列出候选实体、概念、关系、主张。
2. **范围与隐私**：超出 `purpose.md` 先告诉用户。发现凭据、个人隐私、内部主机名则停止写入明文，改用 `<REDACTED>` 或拒绝该段。
3. **搜索已有页**：对每个候选名跑 `rg`（含别名、缩写、中英变体）。读命中页，避免重复建页。
4. **计划**（对用户可见，复杂时先确认再写）：
   - 新建哪些 typed 页
   - 更新哪些旧页（新事实 / 必须保留的旧事实 / 将追加的链接）
   - 对应的 `wiki/sources/` 摘要
5. **先写源摘要**到 `wiki/sources/`，记录关键主张、提到的实体/概念、后续问题。
6. **写或合并业务页**。更新旧页时：
   - 先读全文
   - 锁定 `type` / `title` / `created`
   - 数组字段并集去重
   - 正文整合新事实，不覆盖旧段；冲突并列并标明来源
7. **交叉引用**：相关页加 `[[wikilink]]`；实体-概念关系写在正文，不拼进概念标题。命名规则见 [page-types.md](page-types.md)。
8. **验证**：回读新页；运行 `lint_wiki.py`；error 必须修。
9. **簿记**：`--write-index` 或按同类表格更新 `wiki/index.md`；`wiki/log.md` 追加一行；必要时改 `wiki/overview.md` 的主题/状态，不要删旧综述。

## 合并时不要做的事

- 为了「干净」丢掉旧 `sources` 或旧事实
- 用新标题覆盖身份字段
- 把 raw 文件改写成 wiki 页
- 把源摘要写进实体/概念页而不建 `wiki/sources/` 页
- 在 `wiki/templates/` 下写业务内容

## 完成标准

- [ ] 材料中的关键实体与概念都有页（或已说明为何合并到旧页）
- [ ] 相关页有 `[[wikilink]]`
- [ ] 已搜索、无重复建页
- [ ] 业务页 frontmatter 含 title / type / date
- [ ] 文件类摄入有 `wiki/sources/` 摘要
- [ ] 旧页保留原有信息与来源
- [ ] 已回读并跑 lint，error 为 0
