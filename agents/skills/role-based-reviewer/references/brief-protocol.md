# 输出骨架

单角色用 RoleBrief；多角色或 `mode=review` 用聚合骨架，并保留每个角色的独立结论。

## RoleBrief（`mode=ask`）

```markdown
## RoleBrief

**角色**：<engineer / algo / data / sre / ops / biz / product / design / qa>
**问题视角**：<用户问题的角色化重述，一句话>

### 领域上下文
- 锚点：<本次实际读到的文件路径>
- 运行态：<仅 engineer / sre / ops 需要时填；其余省略>

### 下游建议
- `<skill 或动作>` → <用途一句话>

### 结论
- findings:
  - [path:line 或 符号 — 一行结论]

### 下一步
- downstream：<主责动作>
- 跨角色协作：<主责 / 协作 / redirect；无则省略>

### 总结与置信度
<高/中/低> — <一句原因>
```

## 聚合审查报告（`mode=review`，或多角色）

```markdown
## 审查范围
<目标与边界，一句话>

## 启用视角
<角色列表 + 推断依据>

## 总体结论
<通过 / 有条件通过 / 不通过 + 一句话理由>

## 分级发现
### Blocker / Major
- [角色] 问题描述 — `path:line`，建议修法
### Minor / Suggestion
- <默认省略；仅用户要求仔细审查时列出>

## 按角色结论
#### <角色>
- findings:
  - [path:line — 一行结论]
- 下游建议：`<skill 或动作>` → <用途>

## 跨角色 handoff
- 主责：<角色> — <理由>
- 协作：<角色> — <补充视角>
- 冲突或未知项：<无则明确写无>

## 未覆盖项
<因信息不足未能判断的点>

## 下一步
- downstream：<主责的一个动作；并行时列明任务和顺序>

### 总结与置信度
<高/中/低> — <一句原因>
```

## 字段约定

- **结论绑定**：每条 finding MUST 有 `path:line` 或符号/调用关系
- **建议而非执行**：下游 skill 是建议；本 skill 不代为调用
- **简洁**：上下文已够就直接给结论，不必为填满模板而注水
- **去重**：跨角色同一风险只保留一条分级发现，并标明主责角色；视角明细里仍可各写各的关注点
- **无问题就说无**：不要为凑分级而发明 findings
- **默认不报毛刺**：Minor / Suggestion 受门 3 约束；风格、命名偏好、可选重构不进默认报告
