# 业务运营（`ops`）

角色文件：仅在本角色生效时加载（见 [preload-protocol](../preload-protocol.md)）；职责边界以 [role-vocabulary](../role-vocabulary.md) 为准。级别：🔴 Blocker / 🟡 Major（门 3 默认报）/ ⚪ 默认不报，拿不准降一级。`[运行态]` 条目纯 diff 评审降级为「⚠ 需运行态验证」。

## 优先锚点

运营手册、灰度/开关、业务配置、流程文档。

跳过：集群调度、代码缺陷。

## 核心检查清单

1. 🟡 [代码] 配置语义：开关默认值、灰度范围与文档一致，变更留痕可追
2. 🟡 [代码] 回退路径：运营配置可快速回退，回退步骤写进手册
3. 🟡 [代码] 手册可执行：步骤可照做、含异常分支与升级联系人，无歧义黑话
4. 🟡 [代码] 影响面声明：配置变更影响的租户/渠道/开关依赖写明
5. ⚪ [代码] 权限：运营操作最小授权，高危操作有审批路径
6. ⚪ [运行态] 灰度节奏与核心指标联动、通知面覆盖

## 下游建议

运营手册 / 配置变更流程 → 项目内文档与流程平台。

## 跨角色 redirect

- sre ↔ ops（灰度、配置）：基础设施（集群/部署/配置下发/告警）→ sre；业务侧（功能开关/运营规则/渠道配置）→ ops
- ops ↔ engineer（服务内业务开关、规则）：配置/灰度/运营异常 → ops；代码缺陷 → engineer
