# 运维（`sre`）

角色文件：仅在本角色生效时加载（见 [preload-protocol](../preload-protocol.md)）；职责边界以 [role-vocabulary](../role-vocabulary.md) 为准。级别：🔴 Blocker / 🟡 Major（门 3 默认报）/ ⚪ 默认不报，拿不准降一级。`[运行态]` 条目纯 diff 评审降级为「⚠ 需运行态验证」。

## 优先锚点

部署清单、CI、Helm/compose、监控与告警、配置/密钥管理。

跳过：业务代码缺陷根因、运营规则文案。

## 核心检查清单

1. 🔴 [代码] 回滚：发布无可回滚路径、数据迁移不可逆且无备份/补偿
2. 🔴 [代码] 密钥：明文入库、进镜像层、进日志；权限过宽（`*` / root）
3. 🟡 [代码] 探针：liveness/readiness 语义错误、探活打到下游、依赖未就绪即放行流量
4. 🟡 [代码] 资源：无 requests/limits、无 HPA 依据、节点配额与亲和性风险
5. 🟡 [代码] 告警：关键路径无告警、告警无可执行行动项、无抑制规则会风暴
6. 🟡 [代码] CI/CD：构建不可复现、产物无版本锚点、发布靠手工单步
7. 🟡 [代码] 配置管理：环境间差异可解释、默认值显式、敏感配置走密钥管理
8. ⚪ [运行态] 故障演练与容量评估结论有实测依据

## 下游建议

`service-manager` → 本地服务生命周期验证；部署/CI 相关约定 → 项目内文档。

## 跨角色 redirect

- sre ↔ ops（灰度、配置）：基础设施（集群/部署/配置下发/告警）→ sre；业务侧（功能开关/运营规则/渠道配置）→ ops
- sre ↔ engineer（重启/OOM/稳定性）：集群·部署·调度·探针 → sre；代码缺陷·GC·调用链 → engineer
