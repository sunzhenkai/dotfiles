# 简约与详尽

`.mirror.json` 的 `mode` 是本镜像的主粒度真相；`mode=detailed` 时，`detail_level` 是文件整理粒度真相。切换模式等于该层重写，不是改几个标题。默认 **concise**；进入详尽但未指定文件整理粒度时默认 **important**。

**触发：** 用户点名「详尽 / 每个函数 / 每个变量」→ `detailed`，并让用户选择文件整理粒度：`complete`、`important`（默认）或 `lightweight`。用户点名「每个文件一页 / 给每个源文件写详页」→ 说明本约定，选择 `complete` 或改问热点范围；**禁止**全库铺 `notes/` 或重建 `files/`。

文件有三种角色，详见 [routing.md](routing.md)：清单行、路由键、证据路径。第四种——`modules/<module>/notes/` 热点详注——仅 opt-in。

## concise（简约）

只回答「有哪些文件、各自核心能力是什么」。阅读叶子是**模块 README**。

| 写 | 不写 |
|----|------|
| 模块职责、根路径、文件一览表 | `modules/*/files/` 或为每个源文件建 `notes/` |
| 每个文件 1 句职责 | 局部变量、逐行实现 |
| 核心函数/类型：名字 + 一句职责 | 每个辅助函数的分支逻辑 |
| 概念/实体/处理线的定义与关系 | 把函数体搬进规格 |

「核心」指：对外入口、领域不变式、处理线必经符号。私有辅助、纯胶水、生成代码默认不列。

文件表示例：

```markdown
| 文件 | 职责 | 核心 |
|------|------|------|
| `cmd/server/main.go` | 进程入口 | `main` |
| `internal/order/service.go` | 下单与取消 | `Place`, `Cancel` |
```

## detailed（详尽）

详尽模式先选择文件整理粒度；三档都加深金字塔和切面，但决定模块文件表如何覆盖源文件：

| `detail_level` | 文件处理 |
|----------------|----------|
| `complete` | 完整整理所有源文件；简单文件可以合并登记，但不得遗漏任何文件 |
| `important`（默认） | 只整理重要文件；简单文件可以忽略或合并，**只能忽略没有业务含义的文件** |
| `lightweight` | 沿用当前轻量模式：模块文件表保留必要清单，详尽主要加深模块、实体、处理线、契约和投影，不为普通文件增加详注 |

三档均不是“一文件一页”。文件表仍可一行一个文件；`important` / `lightweight` 可以把职责相同且无独立业务含义的简单文件合并为一行或以目录范围登记，但业务入口、领域规则、状态转换、持久化和协议证据必须保留。

在简约之上**加深同一批页**，不复制一棵源文件树：

| 层 | 加深什么 |
|----|----------|
| 模块 README | 核心符号补参数、返回、副作用、错误如何结束；文件表仍一行一个文件 |
| 实体 | 领域字段、约束、不变式 |
| 处理线 | 每步落到模块 + 符号 + 失败形态 |
| 恢复投影 | 同一批 INDEX（及 `surface/config.md`）写深：邻接协议、存储差、接口目录、拓扑、可再生命令 |
| 契约 | 能追溯 SOURCE；切片尽量到 specified |
| `notes/` | **默认仍不建**。只对用户点名或符合热点条件的路径建 |

实现要点写「怎么做」和「为什么这样」，不要贴大段源码。需要证据时引用符号名和相对路径。

`symbols` 只提供候选名单，用于填模块表和热点页；Agent 必须对照源文件写人话，禁止把 AST 原样倒进 Markdown。不要对全 inventory 逐文件抽符号：只对 `scope` 内、且将写入模块表的文件跑 `symbols`。

## 范围与热点

`detail_level` 通过 `$SPECCTL init --detail-level ...` 或 `$SPECCTL set-sync --detail-level ...` 保存；旧镜像缺少该字段时按 `important` 解释。`mode=concise` 时该字段不改变简约模式的行为。

- `scope`：知识覆盖的源路径前缀；空表示全库（仍走 inventory 忽略规则）。与是否建 `notes/` 无关。
- 简约默认全库。详尽应对 `scope` 或 `inventory --path` 收窄要写深的模块，而不是「详页文件清单」。
- `inventory.file_count` 只作状态展示，**不**再作为是否生成叶子页的开关。
- `set-sync --mode` 与实际写成的粒度必须一致。

### 热点 `notes/`（opt-in）

路径与源树同构：`modules/<module>/notes/<source-rel>.md`（例如 `notes/internal/order/service.go.md`）。不要把 `/` 拍成 `__`。

**何时建（须至少一条）：**

- 用户点名文件或路径前缀；
- 该文件是某条切片的入口（路由/命令/消费者），且模块表写不下入口协议细节；
- 单文件承载多条处理线或非平凡状态机，表行无法说清。

**何时不建：** 为了「详尽看起来完整」；inventory 里每一个代码文件；DTO/胶水/生成代码；已有对应实体页的纯结构体文件。

用户要热点详注且未给路径：先问。建议切片入口，或一次 ≤ **15** 个文件。未同意、或候选将超过 15 个，不得批量建 `notes/`。

页内写：真身路径、为何是热点、表里写不下的符号要点、链回模块/实体/处理线/切片。

热点路径用 `$SPECCTL set-sync --hotspot <path>`（可重复，本轮列表整表写回）回写 `.mirror.json`，不要手改状态文件。模块 README「热点」表仍给人读。

## 更新时

按 [routing.md](routing.md) 把 `diff` 的文件映射到模块，再跟链接改知识层、恢复投影与切面。

- 简约：只改模块文件表和被波及的知识/投影/切面页。
- 详尽：同样改这些页并写深；不要为每个变更文件建或重写详页。
- rename（`status=R`）：改文件表路径（及已有 `notes/` 文件名），不当成删除 + 新增。
- 从 concise 升到 detailed：加深已有页；不要补全量 `files/` 或 `notes/`。
- 从 detailed 降到 concise：停更 `notes/`；除非用户要求删除，否则保留并在模块 README 注明可能过期。
- 遗留 `modules/*/files/`：停更、不自动删除；模块 README 注明可能过期。用户明确要求删除后再删，需要的热点按本节少量重建为 `notes/`。
