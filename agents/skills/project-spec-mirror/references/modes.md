# 简约与详尽

`.mirror.json` 的 `mode` 是本镜像的粒度真相。切换模式等于该层重写，不是改几个标题。默认 **concise**。用户点名「详尽 / 每个函数 / 每个变量」时才用 detailed。

## concise（简约）

只回答「有哪些文件、各自核心能力是什么」。

| 写 | 不写 |
|----|------|
| 模块职责、文件一览表 | `modules/*/files/` 详页 |
| 每个文件 1 句职责 | 局部变量、逐行实现 |
| 核心函数/类型：名字 + 一句职责 | 每个辅助函数的分支逻辑 |
| 概念/实体/处理线的定义与关系 | 把函数体搬进规格 |

「核心」指：对外入口、领域不变式、处理线必经符号。私有辅助、纯胶水、生成代码默认不列。

文件表示例：

```markdown
| 文件 | 职责 | 核心 |
|------|------|------|
| `cmd/server/main.go` | 进程入口 | `main` |
| `internal/order/service.go` | 下单与取消 | `Place`, `Cancel` |
```

## detailed（详尽）

在简约之上，为范围内**每个代码文件**建 `files/` 页，并记录该文件中的：

- 包/模块级变量与常量（跳过密钥和明显测试噪声）
- 类型/结构体字段（领域有意义的）
- 函数/方法：参数、返回、副作用、实现要点（分支、锁、I/O、错误如何处理）
- 非代码文件：该文件在构建或运行中的角色、关键键值（仍脱敏）

实现要点写「怎么做」和「为什么这样」，不要贴大段源码。需要证据时引用符号名和相对路径。

`symbols` 只提供候选名单；Agent 必须对照源文件写人话，禁止把 AST 原样倒进 Markdown。

## 范围

- 简约默认全库（仍走 inventory 忽略规则）。
- 详尽应对 `scope` 或 `inventory --path` 收窄；`file_count` > 80 且未收窄时先问用户。
- `set-sync --mode` 与实际写成的粒度必须一致。

## 更新时

- 简约：diff 里的文件只改模块文件表和被波及的知识页。
- 详尽：变更文件重写对应 `files/` 页，并向上检查模块 README 与知识层是否仍成立。
- 从 concise 升到 detailed：补 `files/`，不要删简约层已有叙述。
- 从 detailed 降到 concise：停更 `files/`；除非用户要求删除，否则保留旧详页并在模块 README 注明「详尽页可能过期」。
