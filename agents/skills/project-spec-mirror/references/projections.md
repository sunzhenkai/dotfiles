# 恢复投影（可运行系统）

金字塔回答「这是什么」。切面回答「怎样可验证地改、迁、验」。本文件的五层顶层回答「只凭镜像能否重建可运行系统」。三者并存，不互相替代。

验收档 **C**：不读源码也应能（1）说明系统边界与邻接，（2）对上对外表面与配置键，（3）重建存储与一致性，（4）画出进程/部署拓扑，（5）从零构建、迁移、启动。不是源码逐行副本，也不是把测试正文抄进 Spec。

## 目录

```text
<spec_root>/
├── context/
│   └── INDEX.md           # 系统在环境里的位置
├── data/
│   └── INDEX.md           # 持久化与一致性
├── surface/
│   ├── INDEX.md           # 对外接口目录
│   └── config.md          # 配置键表（值脱敏）
├── runtime/
│   └── INDEX.md           # 进程、部署、拓扑
└── build/
    └── INDEX.md           # 构建 / 测试 / 迁移 / 启动
```

INDEX 是该层的阅读叶子。仅当 INDEX 放不下时再加页：多个邻接系统、多个存储、多个协议族。不要为每个源文件或每张表建页。

`init` 必须创建上列六个文件；已有镜像在 update 时若缺则先补骨架再改正文。

## 与金字塔 / 切面的分工

| 已有层 | 回答 | 不要塞进这里 |
|--------|------|----------------|
| 概念 / 实体 | 领域词与对象 | 库实例、迁移、一致性模型 |
| 处理线 | 一次业务怎么走完 | 系统级超时/重试/降级目录 |
| 模块 | 代码如何落地 | 进程、端口、部署单元 |
| SOURCE | 事实从哪来 | 配置键语义与环境差 |
| 结构契约 | 必须为真的路由/schema 名 | 完整对外目录与兼容策略 |
| `contracts/runtime.md` | 指标、灰度条件、回滚条件 | 拓扑与启动顺序（走 `runtime/`） |
| VERIFY / TRAFFIC | 如何证明仍真、如何发布回滚 | 构建配方（走 `build/`） |

交叉链接：context → surface / runtime；surface → 结构契约 / 处理线；data → 实体；runtime → build / 模块；build → runtime / VERIFY。

## context/

系统在环境中的位置。没有这页，模块和切片都是悬空的。

INDEX 最少包含：

1. **一句话** — 这个系统对谁、在哪条链上负责什么
2. **使用者** — actor / 角色；没有真人用户则写调用方系统
3. **邻接系统** — 表：邻接 / 方向（入|出|双向） / 协议 / 责任切在哪
4. **信任边界** — 哪些调用过鉴权、哪些是内网、租户如何隔离
5. **质量属性** — 延迟、吞吐、可用、容量中实际约束设计的项；没有则写「未知」并给推断来源
6. **安全** — 认证、鉴权、租户；密钥只写「存在 / 轮换方式」，值写 `<REDACTED>`

不确定就写「未知 / 推断」并标路径。不要编造邻接系统。

## data/

持久化与一致性。实体是领域对象；本层是数据怎么活。

INDEX 最少包含：

1. **存储实例** — 表：名称 / 引擎 / 角色（主数据|缓存|队列|对象存储） / 谁读写
2. **与实体的差** — 哪些实体落在哪；哪些表/集合没有对应实体页（胶水表注明即可）
3. **迁移与索引** — 迁移目录或工具；关键索引与唯一约束（链路径，不贴 SQL 全文）
4. **一致性与保留** — 事务边界、重复投递、保留/归档/删除；没有则写「未知」

多个存储且一张表说不清时，可加 `data/<store>.md`，INDEX 只留地图。

## surface/

必须对上的对外表面。对不上就不是同一个系统。

`INDEX.md` 最少包含：

1. **接口目录** — 表：入口（路由/命令/消息名） / 协议 / 版本 / 一句话 / 处理线或切片
2. **兼容** — 版本策略、废弃、错误码习惯；没有版本则写「无」
3. **对内接口** — 仅当它也是稳定契约时列入，并标明「对内」

`config.md` 最少包含：

1. **键表** — 名 / 语义 / 默认 / 环境差（dev/staging/prod 只写差，不写值）
2. **开关** — feature flag 名与默认开闭
3. 值、口令、连接串一律 `<REDACTED>`

SOURCE 仍登记配置文件路径；本页只写键语义。结构契约仍登记必须为真的 schema 名；完整目录以本层为准。

## runtime/

进程与部署拓扑。`facets/contracts/runtime.md` 仍写指标与灰度/回滚条件，不写拓扑。

INDEX 最少包含：

1. **拓扑** — 表：进程或容器 / 角色 / 端口 / 副本或实例关系
2. **网络与依赖** — 谁连谁、发现方式；链到 context 邻接
3. **启动顺序** — 先存储/总线再应用等；链到 `build/` 的启动命令
4. **健康检查** — 探活路径或命令；没有则写「无」
5. **故障与弹性** — 超时、重试、降级、幂等中实际存在的策略
6. **可观测** — 关键日志/指标/追踪/告警/SLO；没有则写「未知」

compose / 清单 / 单元文件是证据路径，不要把整份 YAML 贴进本页。

## build/

可再生配方：从干净环境到可运行。不是项目对外 README，也不代替 README。

INDEX 最少包含：

1. **工具链** — 语言/运行时版本、包管理器；锁文件只列路径
2. **依赖** — 必连的外部服务；第三方库只列影响运行的约束，不抄全 lock
3. **构建** — 一条可复制的构建命令与产物路径
4. **测试** — 一条可复制的测试命令；链到 VERIFY，不抄测试正文
5. **迁移** — 如何套用 `data/` 里的迁移
6. **启动** — 如何把 `runtime/` 拓扑跑起来（命令或 compose 名）

缺命令就写「未知」并标清单文件路径，不要编造 `make` 目标。

## 恢复完备自检

build / update 结束前核对这些项；任一项做不到就在页内写「未知」与缺口，不要假装可恢复：

| 检查 | 通过标准 |
|------|----------|
| 边界 | 只读 `context/` 能说出 actor、邻接与责任切 |
| 表面 | 只读 `surface/` 能列出对外入口与配置键 |
| 数据 | 只读 `data/` + 实体能重建存储与一致性 |
| 拓扑 | 只读 `runtime/` 能画出进程/端口/启动顺序 |
| 再生 | 只读 `build/` 能构建、迁移、启动（命令可执行或标明未知） |
| 脱敏 | 无密钥、连接串、`.env` 原文 |

`validate` 只检查这六个文件存在，不判断正文是否写满。

## 维护

| 动作 | 做法 |
|------|------|
| 新增 | 源码或清单里能划清的邻接/存储/入口/进程/命令，补进对应 INDEX |
| 更新 | 按 [routing.md](routing.md) 落到投影页，再跟链接改契约/切片/实体 |
| 删除 | 源已消失：表行删除或标废弃；保留 `<!-- manual -->` |
| 已有镜像 | 缺骨架则先建上列六个文件的 stub，再填正文；不删金字塔 |

简约只写表和必填节；详尽加深同一批页，见 [modes.md](modes.md)。
