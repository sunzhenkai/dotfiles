# Pretty View HTML

把用户提供的上下文或文件转成美观、简洁、优雅且适合阅读的 HTML 文档。保留原内容的事实、术语和层次；可以重组信息以改善阅读，但不虚构缺失内容。

默认输出到 `docs/pretty-view-html/`。用户指定其他路径时，以用户要求为准。

## 工作流

1. 阅读全部输入，确认主题、读者、内容边界与主要阅读任务。
2. 检查现有根聚合页和相关输出的标题、摘要与路径，判断是否存在可与本次内容共同维护的相同主题。
3. 若发现相同主题，先提出内容包归类方案并取得用户明确确认；确认前不得写入、移动或覆盖 HTML。没有可靠同主题内容时直接继续。
4. 判断单页或多页。默认单页；只有内容由多个可独立阅读、分享或维护的主题组成，或用户明确要求时才拆成多页。篇幅长本身不是拆页理由。
5. 生成前读取 [references/frontend-design/SKILL.md](references/frontend-design/SKILL.md)，在固定视觉系统内确定与主题相符的字体、版式和一个克制的视觉特征。避免套用与内容无关的通用模板。
6. 若内容需要架构图、流程图、关系图、状态图、时序图或其他 diagram，先读取 [references/html-diagram/SKILL.md](references/html-diagram/SKILL.md)，按其模型选择与绘制原则生成，并嵌入当前阅读页（默认不另建独立 diagram 文件）；配色、导航与页面壳层仍服从本 Skill 的 Chinoiserie 与表达组件约束。优先 HTML/CSS/SVG；仅在信息规模确需时使用 Canvas/WebGL，且保持可离线打开。
7. 直接生成可在浏览器打开的 `.html`；输入 Markdown 只是内容来源，不需要另建 Markdown 副本。
8. 更新内容入口与根聚合页，随后检查视觉、导航、响应式、图解与链接。

## 文件组织

名称使用简短、可辨识的 kebab-case slug。

### 单页

```text
docs/pretty-view-html/
├── index.html
└── <slug>.html
```

单页文档本身是完整阅读入口，并提供返回根 `index.html` 的链接。

### 多页

```text
docs/pretty-view-html/
├── index.html
└── <slug>/
    ├── index.html
    ├── <topic-a>.html
    ├── <topic-b>.html
    └── assets/            # 可选，共享样式、脚本或图片
```

- 包内 `index.html` 是该内容集的聚合页：说明主题、范围并列出全部页面。
- 内容页使用一致导航，至少能返回包首页；适合顺序阅读时再提供上一篇/下一篇。
- 页面较多且存在真实、稳定的父子分类时才增加分组目录；每个分组目录必须有自己的 `index.html`。默认不超过两级内容层次。
- 多页共享的样式和脚本放进包内 `assets/`，不要复制出容易漂移的多份资源。

### 本地链接

所有本地 `href` 和 `src` 必须以**包含该链接的当前 HTML 文件所在目录**为基准计算相对路径。输出目录可能位于任意位置或嵌套层级，禁止假设当前页面位于仓库根、文件系统根或网站根。

- 本地链接使用 `./`、`../` 或不带前导斜杠的同级路径；禁止以 `/` 开头的站点根路径、绝对磁盘路径和 `file://` 链接。
- 不要把仓库相对输出路径硬编码进链接。例如页面实际位于 `<output-root>/index.html` 时，内容入口写作 `./<slug>.html` 或 `./<slug>/index.html`，而不是 `<output-root>/<slug>.html`。
- 内容包首页链接同目录页面时使用 `./<topic>.html`；包内页面返回包首页通常使用 `./index.html`，返回上级聚合页通常使用 `../index.html`。存在更深层级时按实际目录逐级计算，不机械复制示例。
- 样式、脚本、图片、迁移页目标和导航链接遵守同一基准。HTTP(S) 外部链接不受此规则影响。

必须先确定最终文件布局，再分别为每个 HTML 文件计算链接。写入后从每个来源文件的父目录解析全部本地 `href` 和 `src`，确认目标存在且没有越出预期输出范围。

### 同主题内容包

“相同主题”要求内容围绕同一核心对象、问题域或连续阅读任务，并且合并后有明确的共同维护价值；关键词重合、同一文档类型或宽泛领域相同不足以归类。

发现相同主题后，写入前必须向用户展示：

- 归类依据，以及拟纳入和明确不纳入的页面；
- 内容包标题、slug、页面结构和目标路径；
- 现有链接、根聚合页入口和旧路径的处理方式。

只有用户明确确认该方案后，才将相关内容自动重组为同一个多页内容包。重组时保留旧路径的可达性，可用指向新入口的轻量迁移页承接旧链接；根聚合页只登记新的内容包入口。用户拒绝、要求调整或主题关系不可靠时，保持现有文件不动，并按用户选择继续。

## 根聚合页

`<output-root>/index.html` 是所有生成内容的总入口，默认位于 `docs/pretty-view-html/index.html`；用户指定输出路径时，`<output-root>` 就是该目录。根聚合页必须持续维护：

- 每个单页或多页内容集只登记一个入口；多页指向包内 `index.html`。
- 展示清晰的标题、简短说明和必要的日期或类型信息，不暴露实现细节。
- 新增、移动、重命名或删除内容时同步更新，避免死链和重复条目。
- 已存在时保留原有内容与视觉语言，在其基础上增量更新；不存在时创建简洁的响应式索引页。

写入前检查目标路径。若同名内容已存在且用户没有明确要求覆盖，选择不冲突的 slug，或在无法合理判断时询问用户；禁止静默覆盖。

## 固定视觉系统

所有页面使用 Chinoiserie 色板。色值直接写入生成结果，不要求运行时读取主题文件：

- 页面背景 `#ffffff`，次级表面与导航背景 `#e0e0e0`，边框或选中态 `#d6d6d6`；
- 正文 `#4a4035`，次要文字 `#918072`，弱化/注释 `#80766e`，强文字 `#2f2f35`；
- 主强调色、链接和标题强调使用 `#815c94`（紫晶）；
- 主动使用强调色突出重点、状态与结构，避免整页只剩灰阶正文：
  - `#c04851` 朱砂：错误、删除、阻断、高优先级警示；
  - `#fb8b05` 赭石：警告、待决、注意；
  - `#d6a01d` 帝王黄：关键结论、高亮标记、需优先阅读的要点；
  - `#428675` 松石：成功、通过、正向结果；
  - `#2b73af` 孔雀蓝：信息提示、引用说明、外部关联；
  - `#c08eaf` 牡丹粉：次级标签、关键词、可选类别区分；
  - `#945833` 肉桂：元信息、弃用、次级标记。

不要另选色板外的主色或强调色。主题差异通过字体、信息结构、版式、组件选择和一个与内容相关的克制视觉特征表达；重点与状态优先用上述色值编码，而不是只靠字重或灰阶。

每个页面使用一致的顶部导航栏，至少提供根聚合页入口，并在内容包内提供包首页和当前位置。导航栏采用 `position: sticky`、`top: 0` 和明确层级，背景必须足以遮住滚动内容；窄屏可换行或横向滚动，不能隐藏关键入口。

## 表达组件

按内容职责选用具有表达力的语义化组件；组件服务于扫描、对比和操作，不把普通段落一律卡片化。同一多页包共用一套组件语言与色义映射。生成前根据输入挑选足够的组件类型，缺省不要退回“标题 + 灰段落”的模板页。

| 职责 | 优先组件 | 用色提示 |
|------|----------|----------|
| 内容表达 | 结论/摘要条、导语、定义列表、关键引用、分段说明 | 结论可用帝王黄或紫晶边强调；引用可用孔雀蓝 |
| 标签 / 徽章 | 状态徽章、类型标签、优先级标记、版本/受众 chip | 状态映射朱砂/赭石/松石；类别可用牡丹粉或肉桂 |
| 架构 / 可视化 | 分层架构、流程步骤、关系图、状态/时序图、图例、时间线（按 [html-diagram](references/html-diagram/SKILL.md) 选型） | 层级与连线用紫晶/孔雀蓝区分；图例颜色必须有语义 |
| 对比 / 决策 | 对照表、优劣矩阵、方案并列表、决策记录、取舍说明 | 正向松石、负向朱砂、权衡赭石；决策结论加强调色 |
| 教程 / 操作 | 有序步骤、检查清单、命令/代码块、`kbd`、注意事项 callout | 步骤序号用紫晶；警告/阻断用赭石或朱砂 callout |
| 数据 / 状态 | 指标条、进度、状态面板、字段表、结果汇总 | 达标松石、异常朱砂、待定赭石；关键数字可用帝王黄 |

约束：

- 只表达输入中真实存在的信息；不为“好看”虚构指标、状态或对比项。
- 卡片、徽章和 callout 必须编码真实职责或语义；装饰性编号、无意义图标行和卡片海洋禁止。
- 图解按 [html-diagram](references/html-diagram/SKILL.md) 选型与绘制；优先语义 HTML/CSS/SVG，复杂图必须配文字说明与图例，并嵌入阅读页而非默认拆成独立文件。
- 颜色不单独承担全部含义：同一状态同时提供文字标签，并保持足够对比度。

## 阅读与布局要求

- 内容优先：用清晰的信息层级、适宜行宽、稳定节奏和充足留白支持连续阅读。
- 桌面端默认采用偏宽的阅读布局：内容容器宜充分利用视口，常见上限可落在约 `1200–1600px`，配合响应式侧边距与 `clamp()` 内边距；不要默认收成传统窄文章栏。
- 连续长文段落可略收窄以保持行长可读；表格、代码、图解、对照与多栏区域使用内容容器的完整宽度。
- 仍按内容类型、主要阅读任务和视口自适应；不要机械套用单一固定 `max-width` 或正文字符宽度，也不要让局部宽内容反向撑破页面。
- 控制字体数量；装饰仅保留能帮助理解、建立辨识度或承载组件语义的元素。重点、状态与结构差异优先用 Chinoiserie 强调色表达。
- 正文、表格、代码、引用、提示和图片都要在桌面与窄屏上易读；宽表格允许横向滚动，不能撑破页面。
- 使用语义化 HTML，保持标题层级连续，并提供明确的页面标题、语言属性和 viewport。
- 链接和控件具有清晰文本、可见键盘焦点与足够对比度。不要只靠颜色传达含义。
- 动效必须服务阅读，默认克制，并尊重 `prefers-reduced-motion`。纯阅读页不为“高级感”强行动画。
- 优先生成可独立打开的静态页面。除非确有必要，不依赖构建步骤、前端框架或必须联网加载的资源。

## 完成检查

- 输入中的核心事实、代码、表格、术语和结论没有遗漏或篡改。
- 页面没有溢出、遮挡、过小文字、失效资源或明显的模板化装饰。
- 单页可返回根聚合页；多页具有包首页、完整页面地图和一致导航。
- 根 `index.html` 已包含本次内容的唯一入口。
- 发现同主题内容时，归类方案已获用户明确确认，实际路径与确认内容一致。
- 页面使用 Chinoiserie 色板与表达组件，重点和状态有明确配色编码；吸顶顶部导航与偏宽自适应布局在窄屏下仍可用；若含 diagram，已按 html-diagram 选型并嵌入阅读页。
- 每个本地链接都以来源 HTML 文件所在目录解析，目标存在，且没有站点根路径、绝对磁盘路径或 `file://` 链接。
- 所有本地链接与资源路径有效，页面可直接在浏览器中打开。
