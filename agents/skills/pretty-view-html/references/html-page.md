# HTML 阅读页（html-page）

本文件规定 HTML 阅读页的信息架构、页面关系和工程合同。视觉方向同时 Read `frontend-design/SKILL.md` 后从内容推导，不使用固定皮肤。落盘、根索引和交付格式服从上级 `SKILL.md`。

## 两次判断

### 内容模式

| 模式 | 推荐结构 | 重点表达 |
|------|----------|----------|
| `spec` 规格 / RFC / PRD | 状态与摘要 → 背景/目标 → 需求与约束 → 决策 → 追溯 → 未决项 | 决策、状态、可追溯 |
| `visual` 架构 / 对比 / 时间线 | 摘要 → 图例 → 主图/矩阵/时间线 → 证据与解释 | 关系、差异、演进 |
| `doc` 技术文档 / 操作说明 | 摘要 → 目录 → 分节正文 → 示例/代码 → 注意事项 | 查找、步骤、准确性 |
| `article` 报告 / 方案 / 知识 / 长文 | 结论 → 背景 → 要点 → 细节 → 风险/下一步/参考 | 阅读节奏、论证 |
| `review` HTML code review | 范围与结论 → 严重度分组 → 位置与证据 → 测试与残留风险 | 优先级、证据、行动 |

可组合相邻模式，但必须确定一个主模式。模式决定信息结构，不决定皮肤。

### 页面架构

默认单页；按内容边界、受众和维护关系升级：

| 架构 | 使用条件 | 维护单元 |
|------|----------|----------|
| 单页 | 一个主题，适合连续阅读并共同发布 | 一个 HTML |
| 扁平多页 | 多个可独立阅读的同级模块 | 一个包 + `_site.json` |
| 层级多页 | 存在稳定父子分类，分组承担总览职责 | 一个包 + `_site.json` + 分组目录 |

篇幅、标题、表格、代码或顺序关系本身都不是拆页理由。

## 七条核心规则

1. **结构真实**：标题层级、页面层级、导航和组件必须反映真实内容关系，不用视觉形式伪造关系。
2. **内容决定形式**：先确定读者任务和信息关系，再选择版式、组件、字体与颜色。
3. **机制最少**：默认单页、原生 HTML 和少量组件；没有内容职责的 hero、导航、卡片、编号或交互不应出现。
4. **清单统一**：多页以 `_site.json` 为规范依据；页面地图、面包屑、全局导航和前后页必须与它一致。
5. **阅读优先**：连续正文保持可读行宽，仅让确需横向空间的内容进入受限宽区。
6. **本地优先、渐进增强**：`file://` 可用；JS、外网资源或增强效果失败时，核心内容、导航和图解仍可理解。
7. **可访问、可验证**：语义、键盘、窄屏、打印、本地链接和视觉结果都必须实际检查。

具体限制用于落实这些规则；发生冲突时，优先保证内容准确、可读和可访问。

## 内容与视觉 brief（MUST）

Read `frontend-design/SKILL.md`，写代码前在内部确定：

1. **Subject**：主题世界中真实的材料、符号或工作方式。
2. **Audience** 与 **Page job**：谁在什么环境读，读完要完成什么主要任务。
3. **Direction**：一句与主题绑定的视觉方向，不能只写“简洁、现代、高级”。
4. **Tokens**：有语义的颜色、字体角色、间距和圆角；从内容、阅读环境和对比度推导，不预设冷暖色系。
5. **Layout**：内容结构如何映射为版式。
6. **Signature**：一个与主题有关且可解释的记忆点，其余保持克制。

如果 brief 换一篇文档仍完全成立，就过于通用。多页包共用一份 `assets/site.css`、同一 token、网格、导航、组件和交互语言；需要脚本时共用 `assets/site.js`。统一设计系统，不统一成“每段一个卡片”。

## 导航与目录合同

页内目录、站点导航、面包屑、前后页 pager，以及多页 hub 页（`index.html` 及分组 `index.html` 的页面地图）和正文共用同一份 `frontend-design` brief 的 token，但**位置与职责固定**，不因主题换成侧栏树或色块墙。

| 读者的问题 | 机制 | 位置与职责 |
|------------|------|------------|
| 整体还有什么、我可能漏看了什么 | 站点导航 | **页面顶部**横向栏；列出 `_site.json` 中的真实页面 |
| 这页很长，我要跳到某一节 | 页内目录 | **左侧**；链到本页标题锚点，必须可隐藏 |
| 我现在在树的哪里 | 面包屑 | 正文上方路径 |
| 看完这页接下来看什么 | pager | 正文末尾前后页 |
| 这份文档的结构总览 | hub 页地图 | 首页 / 分组首页的内容区，不是第二套导航栏 |

当读者需要非线性查找，或正文结构无法在一个视口内快速掌握时，提供页内目录；短小、线性叙事可以省略页内目录。多页包每页都要有顶部站点导航。hub 页地图是给读者的结构总览，用排版和层次表达关系，不要做成大面积色块或深色横幅。

### 固定布局

1. **站点导航在上部**。横向、单行或自动折行；层级用嵌套列表，不用左侧全高树。与正文同色系，只用底边或细分割，**不得**整栏深色底板、厚色条或色带墙。
2. **页内目录在左侧**。视觉层级低于标题和正文：浅底、正常正文色、缩进与字重表达层级。**必须支持视觉隐藏**：优先原生 `<details>` + `<summary>`，并用 `:has()` 让页面网格响应 `open` 状态，使无 JS 仍可操作。侧栏隐藏后**不得继续占据原栏宽**，隐藏后释放侧栏空间，正文扩展到释放出的空间，只保留清楚、可聚焦的恢复入口（例如竖排或窄条上的「本页目录」），不能留下空白侧栏。
3. 查阅型文档目录默认展开，连续阅读型文章可默认折叠。同一多页包保持一致；打印时展开目录内容。
4. 窄屏时顶部导航与左侧目录都回到文档流，目录仍可折叠。

禁止：把站点导航做成左侧深色树；把页内目录做成顶部横条；装饰性侧栏、刻度尺或图例不能代替导航。

### 工程底线（不因原则化而放宽）

- 使用真实 `<nav>`，并给出能区分职责的 `aria-label`（如「本页目录」「站点导航」「面包屑」「相邻页面」）。链接到稳定、唯一的标题锚点，或 `_site.json` 中的真实页面。
- 页内目录默认收录 H2。只有 H3 承担独立查找目标时才下探一层，不把完整标题树复制成目录，也不收录 H4。
- 站点导航、面包屑必须与 `_site.json` 的标题、顺序和层级一致；当前页面用 `aria-current="page"` 标出。页内目录的当前章节提示是可选增强，只有能可靠跟随阅读位置时才显示，并使用 `aria-current="location"`；不能可靠同步时，宁可只保留普通链接。
- 键盘可操作，焦点可见。无 JS 时核心链接仍可用。展开/收起使用原生 `<details>` 或真实 `button`（同步 `aria-expanded` / `aria-controls`），禁止只靠 hover、颜色或图标表达状态；不得因此折叠正文、关键约束或当前阅读位置。
- 页内跳转后标题不能被 sticky 页眉遮挡。

## 页面合同

### 单页

```text
YYYY-MM-DD-<slug>.html
```

- 一个 H1；决策、报告和说明类内容优先给结论，叙事内容服从阅读节奏。
- 页面壳全宽，正文遵循「阅读宽度」；不提供阅读宽度切换。
- CSS 可内联；图片使用同目录相对路径。

### 扁平多页

```text
YYYY-MM-DD-<slug>/
├── index.html
├── _site.json
├── topic-a.html
├── topic-b.html
└── assets/
    ├── site.css
    └── site.js          # 可选
```

`index.html` 是唯一对外入口，给出摘要、范围和完整页面地图；地图的设计服从「导航与目录合同」，不是默认卡片网格。内容页保持同级关系，并按 `_site.json` 提供首页、前后页或同级导航。

### 层级多页

```text
YYYY-MM-DD-<slug>/
├── index.html
├── _site.json
├── domain-a/
│   ├── index.html
│   └── topic-a.html
└── assets/
    ├── site.css
    └── site.js          # 可选
```

默认最多两级内容页；更多层级必须由稳定分类和明确导航收益证明。每个分组 `index.html` 解释分组并链接直属子页，设计上同样是一份 hub 页地图；内容页提供“首页 → 分组 → 当前页”面包屑和同级导航。

## `_site.json`：多页规范清单

多页必须创建 `_site.json`，集中声明标题、路径、顺序和层级。它是一致性检查依据，不宣称能自动生成页面。

```json
{
  "title": "展示包标题",
  "home": "index.html",
  "pages": [
    {
      "title": "领域 A",
      "path": "domain-a/index.html",
      "children": [
        {"title": "主题 A", "path": "domain-a/topic-a.html"}
      ]
    }
  ]
}
```

- `path` 是不以 `/` 开头、不含 `..` 的包内相对路径。
- `title` 与对应页面 H1 一致；扁平包不使用 `children`。
- 层级父节点指向真实分组 `index.html`。
- 页面文件不得游离于 `_site.json`；资源文件和根 `index.html` 除外。

页面变更顺序：先改 `_site.json`，再改文件、地图和导航，随后检查死链、重复路径、孤儿页、H1 与顺序，最后更新根 `docs/pretty-view-html/INDEX.md`。禁止只改单页导航。

## 阅读宽度

阅读页不是全宽仪表盘。行长过长或过短都会拖慢阅读速度，这是选择宽度的原则依据，不是审美规定；下面的数值是从这个原则推导出的默认起点，内容确有需要（复杂图解、对照网格、密集代码）才升级到宽内容区。页面壳铺满视口，连续正文默认 `max-width: 68ch`，中文为主或字号较大时可收至约 `60ch`；宽内容区默认 `max-width: min(100%, 110ch)`。

```css
.page { width: 100%; }
.page > * { max-width: 68ch; }
.page > .wide { max-width: min(100%, 110ch); }
```

代码、复杂图解、对照网格或确实较宽的表格才使用 `.wide`。有侧栏时宽度在主栏内计算；窄屏使用扣除页边距后的宽度。禁止用 `max-width: none` 无限拉长内容，也不为宽度引入 JS。

## 组件与表现规则

组件的选择服从内容真实的关系，不是审美偏好；以下是常见判断的例子，换一批内容就该换一批组件，不是清单式必须逐条套用。

- 摘要只放结论；探索型或叙事内容不强制 TL;DR。
- 时间演进用时间线或步骤；同级可比对象用卡片或对照网格；字段、指标、差异和追溯关系用表格。只有关系值得强化时才转换表现形式。
- callout 只承载决策、风险、阻断或必要提示；普通章节和段落不逐段卡片化。
- 移动端保留表格全部信息并允许容器滚动，不静默删列。
- 编号只表达真实顺序；状态、标签、粗细、斜体和颜色保持稳定语义，不依赖颜色单独传达信息。
- 引用、代码、路径和数据紧邻结论；关键约束不藏在 hover 或折叠区。

## 文本定义图

Mermaid、PlantUML、Graphviz/DOT、D2 等文本定义图必须同时交付渲染图片和原始代码：

- 构建时渲染为本地 SVG 或 PNG，不依赖浏览器外网运行时。
- 提供“图片 / 代码”切换；默认显示图片，代码视图完整保留可复制源码。
- 控件使用真实 `button` 并暴露状态；图片有准确 `alt`，复杂图另附文字说明。
- JS 失败时至少保留默认图片和可访问源码；打印默认输出图片。

普通代码块、ASCII art 或字符排版不适用，除非它们被当作结构图阅读。

## 工程与交付验收（MUST）

- 完整文档包含 `<!DOCTYPE html>`、与正文语言一致的 `lang`、charset、viewport 和准确 `<title>`。
- 使用语义 HTML、一个 H1、连续标题层级、跳转链接和可见键盘焦点。
- 本地 `href/src` 使用相对路径；默认不依赖外网 JS、字体或图标。
- 页面响应到窄屏且自身不横向溢出；宽表和代码仅在自身容器滚动。
- 尊重 `prefers-reduced-motion`；JS 失败时核心内容可读；打印隐藏无关导航并保持正文可读。
- 检查桌面和移动端：主题与入口是否清楚，目录和导航能否准确跳转，正文与宽区是否受限，长标题/表格/代码是否溢出。
- 检查多页地图、面包屑、导航和返回路径；检查图解切换、键盘、对比度、减少动效和打印。
- 不把密钥、内部 URL 或公司私有内容写入公开产物。

发现问题就修正并复核。禁止先写临时 Markdown 再转换、复制万能模板、把阅读页做成营销 landing page、让多页清单与导航漂移、手写根 catalog 回链或修改 vendor reference。
