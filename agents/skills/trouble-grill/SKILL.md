# Trouble Grill —— 排查根因时拷问自己

排查复杂根因（多轮、易发散）时，用「锚点 + 假设板 + 门禁」自我拷问。不是流程编排，是三把防失焦的闸门。

**不适用**：单步可复现、报错信息直接指向原因的问题——直接修，不上板。

## 先立锚点

排查开始，把要回答的问题钉成一句话、**可证伪**的锚点：量化差异、带比较基线，写得出「观察到什么，锚点就错」。之后所有动作只服务于回答它。

- 对：锚点 =「环境 A 上接口 X 的 P99 为什么比环境 B 高 5.8 倍」
- 错：锚点 =「接口 X 为什么慢」（太泛，必然失焦）

每次想发散前先问：**这个动作能推进回答锚点吗？** 不能就不做。

## 假设板：强制分级，禁止越级

每个可能的解释都上板，标四件事：

| 字段 | 取值 |
|---|---|
| 状态 | open / ruled-out / confirmed |
| 证据等级 | fact（多源复现）/ strong（单源可靠）/ weak（小样本·单字段·混淆未除）/ guess（纯推断） |
| 依据 | 哪条数据、怎么得出 |
| 预测 + 验证动作 | 「若成立则应观察到 Y」+ 获取 Y 的具体动作（跑哪条查询、改哪个变量） |

**预测不能为空**：写不出可观察预测的假设是 vibe，sharpen 或丢弃。验证动作超过一轮未执行的假设不许留在板上——要么执行，要么降级并注明原因。

**状态转换有条件，不许随手标**：

- open → confirmed：过下方四道门，且证据达 `fact` / `strong`。
- open → ruled-out：有反证数据，依据栏写明哪条数据排除了它。

**铁律**：只有 `confirmed` 才能叫「根因」；`weak` / `guess` 只能说「线索/方向」。

**措辞规范**：全程提到未坐实的假设必须带等级标签（如「[weak] 缓存穿透」）；只有 `confirmed` 才允许写「根因是 X」。最常见的失守不是下结论那一刻，而是「最可能方向」在后续轮次被悄悄当成根因。

### 证据等级怎么升：不许越级，但可以升级

- guess → weak：看一眼真实数据（一条日志、一行记录、一次复现）。
- weak → strong：第二来源复现；或控制变量后差异仍在。
- strong → fact：多源复现 + 反事实成立（改掉 X 问题消失，改回 X 问题复现）。

## 四道门禁：open → confirmed 前必须全过

### Gate 1 能量级

这个根因能解释核心观察的**量级**吗？算一遍。

- 例：「缓存命中率差异」解释 24 倍 P99 差 → 缓存通常只解释 2~5 倍，过不了，淘汰。

### Gate 2 覆盖度

能解释**全部**核心观察，还是只解释其中一条？

- 例：「客户端版本差异」解释了全量用户的差异，但解释不了单个实例内的差异 → 覆盖不足。

### Gate 3 因果 vs 相关

是因果，还是只有相关？判据用反事实：固定其他变量、只改疑似原因，看问题是否随之变化。

- 例：「字段 X 缺失」和「报错多」相关，但 X 不是必填、缺失一直存在 → 没建立因果，只是线索。

### Gate 4 可证伪

同锚点标准：写出回退条件——观察到什么，结论就错？写不出 = 不可证伪 = 不能 confirmed。

四道门任一不过，只能报告「最可能方向 + 证据等级 + 缺什么证据 + 下一步」。

## 失焦检查：切换方向前

1. 新方向回答锚点吗？还是「因为查得动所以查」？
2. 是**决定性证据**，还是边角料？
3. 我是不是刚被证伪、在逃避地换方向？

## 发散检查：卡住/打转时

连续两轮无进展，或反复「找到根因又推翻」时：

1. 我排除了哪些方向？排除依据是**数据**还是**想当然**？逐条重审。
2. 有没有我完全没考虑的方向？
3. 最近 3 个「结论」，是不是同一个假设换皮？

## 收口规则

- 下「根因是 X」前，先问一句**置信度**：我只在哪些范围（样本 / 环境 / 时间窗 / 对照组）里验证过它？逐条点名没验证的维度，回答「换到那里还成立吗？」。全部能答 → 照常收口；有答不出的**盲区** → 结论降级为「在 X 范围内成立 + 盲区 Y」，置信度随验证范围缩小而标注。
- 有 `confirmed` 假设 → 下「根因是 X」，并写回退条件（Gate 4）。
- 没有 → 报告「最可能方向 + 证据等级 + 缺什么证据 + 下一步」，明确「未坐实」；不为「闭环」放松门槛。

## 落盘：每轮收口自动总结三件事

排查过程中——每轮收口、每次用户纠正、每次切换方向前——把三样东西追加到持久化记录，不要只留在对话里：

1. **证据 evidence**：本轮发现，带证据等级（fact/strong/weak/guess）+ 依据（哪条数据）。
2. **用户输入 user input**：用户给的关键信息/纠正。它往往直接推翻某个假设，必须记，否则下一轮会重复踩坑。
3. **排查路径 path**：走过的方向，标 `dead-end`（死路，注明为什么）还是 `alive`（仍有线索）。

追加格式（追加，不覆盖）：

```markdown
## YYYY-MM-DD 第 N 轮
- 锚点: ...
- 证据: [fact] ... ; [weak] ...
- 用户输入: ...
- 路径: 方向A → dead-end（因为 X）; 方向B → alive
```

推荐保存位置（按优先级）：

- 在 task-explore 任务里 → `tasks/ongoing/{task-name}/TASK.md` 的「进展」段；
- 无任务台账 → `archives/sessions/{date}/{slug}.md`；
- 跨会话的偏好 / 已坐实结论 → 有持久记忆工具（如 MCP 记忆服务）则同步，没有则写回台账文件。

**铁律**：被证伪或用户纠正的瞬间就落盘，不要攒到收尾。落盘时只记「证据 + 输入 + 路径」，不抄聊天记录。
