# 审阅给出定级和改进意见，循环修改直到达到预期或诚实结论

- target: agents/skills/task-wizard
- mode: update
- patch: 20260925-052211-review-suggest-loop
- risk: high
- status: proposed

## Intent

Goal 方案的审阅循环是：出方案 → 评审（定级 + 改进意见）→ 修改方案 → 再评审。定级不单独结束循环。改进意见写清改哪一条完成判据或步骤，并指回已有知识、已有方案或公开方案。改进意见为「已达到预期」才进入「写完之后」。

只有审阅者非常确信，对照已有知识、已有方案、公开方案也无法再进一步完善以达到预期时，才停。退出点仍是「审阅不通过」，回复写明预期以及这三处为什么补不上。定级为低或中、同一缺口还在，本身不是这个结论。给出结论前须已对照过这三处。

只有定级、没有改进意见、也没有诚实结论：再叫一次审阅者。第二次仍没有，用「审阅没有结论」。

非目标：不改任务方案的 grill 衔接；不把简单和中等的每一轮审阅都做成外部参照；不改线上动作、泄密、危险操作等其余退出点；完善期间仍不改代码。

## Conflict check

与 `20260925-051644-review-refine-not-exit` 冲突：该轮用「同一缺陷再审仍在」作为「审阅不通过」。本轮删掉这个机械停点，改成对照三类来源后的诚实结论。高且无缺陷不再单独作为开工门，开工门改为改进意见「已达到预期」。

`openspec/specs/task-wizard-goal/spec.md` 与 `docs/adr/0027` 仍写着同一缺陷即停。二者不在本 patch 路径内，应用后另改。

## Rationale

只给定级时，执行者不知道改哪一句。同一缺口再出现，往往还能从已有知识、已有方案或公开方案里找到下一条改法；把它当成失败会再次把完善做成退出。循环继续改方案。确信这三处都补不上预期时，把结论写明，不再空转。

用户已点名该流程与诚实结论。高风险门禁按此具体行为视为通过。
