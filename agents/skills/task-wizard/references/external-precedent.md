# 外部参照

术语见 [../CONTEXT.md](../CONTEXT.md)。只在复杂档、方案定稿前做一次，避免闭门造车。

## 何时做

本仓摸底之后。档位这时是复杂，或写方案时升到复杂：定稿前做完这一次，再写建议路由。路由按做完之后的事实重判。没有复杂档典型情况时可以低于初步档位。已经命中复杂档时不得降档。已经记下的外部参照留在前提里。

档位不是复杂时，回到方案正文继续写。

## 一次尝试

只追最会影响步骤的那一个做法。两个做法分不出主次时，追更没把握的那个，另一个写入假设。

用当前宿主已有的能力检索公开资料，并阅读最多两处公开原文。原文是公开仓库或上游文档里写下该做法的那一处。

本仓的代码和文档算摸底。本机其他仓库，仅当该项目本身公开时才算外部参照。

## 写入前提

- 对上原文：写入事实。一句话写出做法，并附上公开出处。做法会改步骤时，改步骤。
- 打不开、没有检索或阅读能力、没有命中、或只有转述：写入假设，写明缺的是什么。方案照常写完。
- 两处原文都对上、做法相反：两条都写入事实，各自附上公开出处。步骤采纳一条，另一条写入坑。没有已查证事实能选定哪条时，这是决策点。

事实和假设仍写在前提里。步骤里写采纳之后的动作。

## 做完

前提里写明这一轮追的是哪一个做法，以及结果落在事实、假设，还是两条相反的事实。然后才定稿。

## Goal 方案

审阅之前写入前提。会改步骤或完成判据的假设，走现有退出点「理解不够」。只写入坑、不改步骤的，继续审阅。沿用现有退出点。
