# 外部参照

为补方案读到的一条公开做法。对上公开原文的是事实，对不上的是假设。复杂问题里会改方案走向的做法，比较方案之前没有这次尝试，就是闭门造车。

`explore` 与 `design` 在阶段详情指向本文件时读取。`chat` 只读本仓代码与任务里已有笔记。

## 何时做

- `design`：写对比表之前做一次。
- `explore`：只有这个未知会改方案走向时做。其余问题照常问。
- 同一问题、已记下的出处仍对得上：沿用已有条目。
- 问题变了、出处对不上、或当时记的是未找到：再做一次。

## 一次尝试

只追最会影响方案走向的那一个做法。两个做法分不出主次时，追更没把握的那个，另一个记为假设。

用当前宿主已有的能力检索公开资料，并阅读最多两处公开原文。原文是公开仓库或上游文档里写下该做法的那一处。

当前仓库的代码和文档是摸底。本机其他仓库，仅当该项目本身公开时才算外部参照。

## 写入

- 对上原文：记为事实。一句话做法，加上公开出处。
- 打不开、没有检索或阅读能力、没有命中、或只有转述：记为假设，写明缺的是什么。方案照常往下写。
- 两处原文都对上、做法相反：两条都是事实，各自带公开出处。对比表可以把这两条当作两个方案。

落盘时写入设计稿的「外部参照」一节。更新 `TASK.md` 方案时，事实和假设分列，假设保持为假设。

## 做完

笔记里写明这一轮追的是哪一个做法，以及结果是事实、假设，还是两条相反的事实。然后继续本阶段原来的下一步。
