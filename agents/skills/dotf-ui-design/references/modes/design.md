# Design 模式

新建界面，或重塑既有界面的视觉方向。产出是直接实现的界面代码。品味内核细节按 [../frontend-design/SKILL.md](../frontend-design/SKILL.md) 执行，要点：

- **扎根主题**：设计出自产品自己的世界——行业、材料、器物、行话；不是任何项目都能用的默认值。
- **一个记忆点**：大胆集中在一处，其余保持安静克制。
- **结构即信息**：边框、编号、eyebrow、分隔线只在编码内容的真实信息时使用。
- **动效克制**：非用户触发的动效只为引起注意；一段编排好的时刻胜过满屏散点效果。
- **文案是设计内容**：CTA 说清会发生什么，动作命名全程一致，错误与空态给方向而非情绪。
- **反模板自检**：AI 生成设计当前聚类的几类默认脸（校准清单见 ../frontend-design/SKILL.md）；brief 留白的自由轴，不要花在这些默认值上。

## 0. Recon（动手前）

- 定位目标 surface：路由、页面入口、组件层级，确认改的是哪份代码。
- 识别既有约束：项目的设计系统（DESIGN.md、token 体系、组件库）、样式组织方式（CSS Modules / Tailwind / 全局 CSS）、可复用 primitive 及其 owner。
- 确认验证方式：能否运行、能否截图、typecheck / lint / build 命令是什么。
- 项目已有治理当前界面的设计系统时，所有决策落在它的 token 与组件上；不另造平行体系。需要新建或治理设计系统时，明确转交 ui-template-design，不在本模式内造体系。

## 1. 定题

brief 没写清产品或主题时，先自己钉死一个具体主题、受众和页面的唯一任务，作为提案向用户确认，再动手设计。

## 2. 两遍法

- 第一遍出紧凑 token 方案：Color（4–6 个命名 hex）、Type（字体与角色）、Layout（一句话概念 + ASCII 线框 + 对齐策略）、Principles（本页独特性的高层指引）。
- 第二遍对照 brief 反模板自检：任何一部分若换成相似 brief 也会长这样，就重做该部分并说明改了什么、为什么。确认相对独特后才写代码。

## 3. 实现

每个颜色与字体决策从修订后方案推导；注意 CSS 选择器优先级互相抵消的问题（尤其 `.section` 类选择器与元素选择器之间的 padding/margin）。只写用户指定范围内的界面。

## 4. 自评与闭环出口

- 截图复查按 [../visual-evidence.md](../visual-evidence.md) 取证——一张图值 1000 token；按"出门前摘掉一件配饰"做删减。
- 守住质量底线（移动端响应式、可见键盘焦点、prefers-reduced-motion、视觉可访问），但不宣传它。
- 交付时说明关键决策的出处、验证方式与结果。
- 闭环出口：实现被接受后，可建议用 audit 模式对照设计系统验收，把偏差沉淀为 design-plans/ 计划（见 [../plans.md](../plans.md)）；也可走 [../review.md](../review.md) 做 diff 级独立验收。
