# Solo UI 设计语言（纸墨编辑感）

本文件定义一套可复用的视觉与交互语言，面向**内容产品**（博客、知识库、编辑器型工具）及其同构后台/个人中心。`SKILL.md` 负责执行流程与冲突裁决；本文件回答「界面应当长什么样、如何判断没有走偏」。

类名（如 `.article-shell`）是推荐约定；落地时映射到项目既有 token / utility，不必照搬字面。

## 核心气质

界面应像被认真编辑过的刊物：克制、清晰、有留白；靠字体、行宽、密度和语义色建立层级，而不是卡片堆叠、渐变、发光和大面积装饰。它不是营销站、仪表盘模板或通用后台皮肤。

- **单一强调色**：品牌只保留一种强调色。状态语义色（成功/危险/警告）可以存在，但不承担第二品牌色。
- **内容优先**：任何装饰都必须帮助理解、导航或阅读；不能说明价值的装饰应删除。
- **同构但不同质**：展示面、管理后台、个人中心共用壳层密度、操作语法与身份约定；后台保持工具属性，不做成品牌营销页或阅读面。
- **默认克制**：未经用户明确要求，不引入紫色/多色渐变、glow、散乱动效、全屏 hero、营销 dashboard 或前台卡片网格。

## 字体与排版

- 标题用有个性的衬线（或项目指定展示字体），正文用清晰无衬线，代码用等宽；不以 Inter / Roboto / Arial / Geist 作为品牌正文字体的默认答案。
- 优先复用项目预设的标题/正文/导语/长文排版角色，不要用临时 `text-*` / `h-*` 组合重造层级。
- 标题可用 `text-balance`，段落可用 `text-pretty`，数字或统计用 `tabular-nums`。
- 阅读正文列跟随文章壳宽，不二次收窄；宽元素（`pre`、表格、图表）可横滚，但不破坏整体阅读节奏。
- **长文排版单一来源**：编辑器预览与正式阅读面共用同一套 prose 规则，避免两端间距/链接样式漂移。列表项内含段落时，应收紧 `li` / `li > p` 间距，避免默认三重 margin 把列表撑空。
- **刊表格**：轻外框承载横滚；单元格淡色内线（勿硬边铁丝网）；表头与内线拉开对比；偶行极淡斑马纹；单元格紧凑；勿对 `table` 用 `display:block`（破坏 `border-collapse`）；勿加卡片阴影或强调色实心底。
- **文字链接基线**：小手、无下划线；hover/focus-visible 时字色与背景反转（背景取原字色/墨色，字色取纸色），轻量圆角。反转块紧贴文字、不向外扩张（禁止用水平 padding + 负 margin 撑大 `scrollWidth`，也禁止用 `box-shadow` 外扩——会被 `truncate` / `overflow:hidden` 裁成不对称）。若组件层与 utility 层冲突，反转字色/背景需能盖过页面级 `text-*`。禁止 `underline` / `hover:underline`，禁止再用「变色 + 加粗」当作文字链唯一反馈。
- **文字链字号档**：操作/导航文字链统一三档（small / normal / large），**默认 normal**；禁止用临时字号把单条操作链撑偏。标题本身是链接时随标题层级，不套此三档。

## 色彩与主题

- 优先语义 token（`background` / `foreground` / `muted` / `primary` 等），原始色值只作分类到 token 的中间步骤。
- 浅色与深色 token 成对维护；改一边必查另一边。
- 品牌强调色是锚点，不引入无理由的第二强调色。
- 上游示例、preset、设计概念只能映射到现有 token 与字体角色，不能顺带替换项目品牌方向。

## 壳层结构

常规页面遵循分段壳层，并以同行密度为默认：

```text
nav（整页居中）+ tools（同行靠右）→ title（居中）→ meta + actions（同行，可空）→ content → [brand 页底]
```

- **Header**：主导航在整页宽度内水平居中，图标工具与菜单同一行并靠右；纵向居中对齐。常规 header、导航和工具区禁止 sticky/fixed。
- **菜单选中态**：选中靠字重/前景色 + `aria-current="page"`（或等价 `data-active`），未选中 muted；hover/focus-visible 与文字链接基线一致（字色背景反转）。首页仅精确匹配，其余前缀匹配。
- **Brand**：位于页面底部（文档流，非 fixed）；不承担导航/回首页职责。短内容时用 `min-h-dvh` + `mt-auto` 贴视口底；长内容时在文档末尾。footer 以 brand 为主，避免堆辅助链接。
- **信息唯一**：同一可见信息只表达一次——可见标题、菜单项、brand 与工具入口不得重复表达同一信息。可见标题被移除时保留 `sr-only` h1，当前位置由 active 菜单态承担。
- **展示面**：阅读面用页面标题/导语角色；主导航与工具区规则见上。
- **后台**：主导航纯文字，工具区纯图标（含身份入口）；走通用内容宽。
- **个人中心**：子导航纯文字，不展示 role；走通用内容宽。

## 内容宽度（原则）

内容宽只分两档，新页面必须先归类再套壳，禁止再发明第三档或页面私有 `max-w-*`：

| 档位 | 推荐约定 | 用途 | 原则 |
| --- | --- | --- | --- |
| **文章内容宽** | `.article-shell` | 文章、独立页、预览等阅读面 | 阅读面必须用此档 |
| **通用内容宽** | `.content-shell` | 列表、搜索、后台、设置、个人中心等 | 非阅读面必须用此档 |

- 正文列跟随文章壳宽；宽元素可横滚，不另开壳宽档位。
- **取值可调，归类不可破**：调整 `max-w-*` 只改实现，不改「阅读面 / 非阅读面」二分。
- 登录错误等特殊居中卡片可保留更窄宽度，不计入内容宽档位。
- 阅读偏好（式中/宽屏、全屏、目录显隐）是**内容列**行为，不得新增第三档内容壳类名。

## 密度与布局

- 菜单与工具同一行：菜单整页居中、工具靠右；窄屏菜单可横向滚动，但不引入吸顶导航。
- 页面描述与 actions 同时存在时同一行；筛选 label 与控件横排。
- 同行控件等高：同一行的输入框、按钮、触发器等高度必须一致，对齐同一档。
- **字段竖叠**：Label 在上、控件在下时，外层统一字段叠放间距（推荐 `flex flex-col gap-2` 一类约定）；禁止用更紧的私有 gap 拉近 label↔输入。字段组之间用表单级间距，与字段内间距分开。
- 标题与其日期/作者等 meta 同行两端分布，meta 不占独立行；窄屏允许换行收缩。
- **内容列表（阅读面）**：标题克制；简介可紧随标题、更淡更窄，不必占独立段落；分类/标签单独一行；列表项之间靠间距与轻微 hover tint 区分，不用分割线卡片化；按时间分组时用居中、小字、淡色的年月提示，不作粗标题或卡片。
- 同类内容块在不同页面使用同一内容宽档位。

## 操作语法

默认表面中，同一动作的图标与文字二选一，不得并排双表达。

| 场景 | 形态 |
| --- | --- |
| 壳层工具、列表「新建」、行内次要操作、可图标化的筛选 | 图标 + `aria-label` + Tooltip（或等价悬停/焦点提示） |
| 管理页新增表单 | + 图标触发器 → Dialog 承载表单；禁止页面常驻新增表单与原生 `prompt`/`confirm` |
| 编辑器次要操作、行级详情入口 | 图标 + Tooltip → 直接执行或 Dialog 承载详情 |
| 次要导航、说明性动作、无需图标语义 | 加粗文字链接/触发器，字号默认 normal |
| 页面级表单主提交、空态唯一主操作 | 允许实心/描边 CTA（弹窗 footer 除外） |

- 主导航标签可读优先，工具动作图标优先。
- 图标动作必须有 hover/focus 文字提示；`aria-label` 不能替代可见提示。
- Tooltip 触发器挂在外层包装上，不与 Button/Link/DialogTrigger 合并为同一节点（合并会导致角色与点击争用）。
- 触摸设备依赖可见名称与可聚焦控件，不单靠 hover。

## 弹窗（Dialog / AlertDialog）

- **Footer 形态**：无分割线、无底色、不负边距撑满；与上方内容保持适度间距。
- **Footer 按钮一律文字链**：正向动作用链接态按钮；危险操作用警示色链接态。禁止在弹窗 footer 使用实心/描边 Button。
- **文案克制**：标题已表达的信息不用描述重复；不写操作教学；字段标签不加「（可选）」后缀；placeholder 只给最短示例；状态描述一句话。
- **错误防溢出**：弹窗内错误信息容器必须可断行（长 token / JSON），不得撑破弹窗宽度。

## 身份与互跳

- 壳层身份区为用户图标入口：hover/focus 示名，点击进入个人中心；不展示 role，不常驻用户名文字。
- 身份图标即个人中心入口，不再提供第二个独立「个人中心」工具图标。
- 未登录时使用登录图标入口。
- **工具区靠右固定顺序**（左→右）：模块特有 → 互跳（进后台 / 回首页）→ 语言（若有）→ 主题 → 个人中心（或登录）。各模块不得打乱后几项相对顺序。
- 有权限的用户才显示后台入口；访客/未登录不显示。
- **登出**不在壳层工具区：放在个人中心资料页，与「保存」等同级；壳层禁止登出图标。

## 列表、表格、分页与空态

- 后台数据表统一有边框形态：外框、表头背景/分隔、一致单元格内边距，并填满父内容区。
- 记录型列表使用真表格与表头行，禁止用列表伪造成表格。
- 同类列表不混用无边框与有边框作为默认风格。
- 时间默认用相对时间，hover 展示绝对时间（`<time datetime>`）。
- 分页唯一、位于列表右下角；空列表或仅一页时不渲染。
- 空态为纯文字、居中、辅助色、无边框；支持新建时在空态旁给 + 图标入口。
- **写后立即见数**：新建/删除/更新成功后须立刻展示最新数据；若本地 state 缓存了初始 props，props 变化时必须同步回本地，禁止只刷新却继续渲染过期副本。

## 动效与可访问性

- 动画只在用户明确要求或确实帮助理解时加入；只动画 `transform` / `opacity`；交互反馈不超过 200ms。
- 涉及动画时必须检查 `prefers-reduced-motion`。
- 图标按钮必须有可访问名称；破坏性操作使用确认对话框；错误显示在触发动作附近。
- 改主题/token 时检查浅色与深色；改壳层/操作区时检查手机尺寸、键盘焦点、Tooltip 和空态/错误态。

## 双语与长文本（可选）

若产品为多语言界面：面向用户的文案（含 `aria-label`、Tooltip、占位符、空态、metadata）走 i18n，不在渲染输出硬编码。布局不要写死窄列宽或滥用 `whitespace-nowrap` / `truncate` 掩盖换行；译文通常更长，应允许自然换行（`text-pretty` / `text-balance`），横向滚动只用于代码块/表格等结构化内容。

## 验收提示

完成 UI 改动时至少核对：

- 是否仍是纸墨编辑感、单一强调色、有意图的字体体系。
- 是否符合分段壳层、同行密度、页底 brand、导航居中+工具靠右、导航不吸顶。
- 竖叠 Label+控件是否统一字段叠放间距。
- 是否按内容类型选用文章壳或通用壳，以及统一分页/空态。
- 是否避免前台卡片堆砌、后台营销化、图标+文字并排堆叠、无依据动效和第二强调色。
- 是否保留 Tooltip / `aria-label`、用户图标身份入口、权限互跳、表格边框与填满。
