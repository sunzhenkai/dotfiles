# solo-ui-design — 纸墨编辑感 UI 规范

本 refer skill 沉淀自 Solo 内容产品线的 UI 实践，已剔除项目特例，只保留可复用的设计原则与工作流。完整视觉语言见 [DESIGN_LANGUAGE.md](DESIGN_LANGUAGE.md)。

动手前先读项目现状：若项目已有设计 token / 组件库 / 同类页面模式，**沿用并映射到本规范**，不要另起一套平行实现。项目规范与本文件冲突时，以项目为准并向用户说明；用户明确要求变更品牌方向时，以用户当前要求为准。

## 冲突裁决

仅按以下顺序决策，较低层不得覆盖较高层：

1. 当前用户明确、合法且可实现的要求。
2. [DESIGN_LANGUAGE.md](DESIGN_LANGUAGE.md) 与项目既有设计基线。
3. 可访问性、运行正确性、响应式与性能底线。
4. 本 skill 的模式规则和验收标准。
5. `references/` 下上游补充资料（仅细节，不推翻以上）。
6. 默认审美偏好。

「纸墨编辑感」是本规范的默认边界，不是对用户明确变更品牌方向的否决。上游资料中的强制措辞在本规范仅为第 5 级补充。

## 选择一种主模式

| 意图 | 模式 | 产出边界 |
| --- | --- | --- |
| 新页面、重塑气质 | Design | 先定色、字、布局和一个签名元素，再实现 |
| 小范围修 spacing、层级、排版、布局 | Optimize | 只改已确认表面，不借机重做 |
| 评审、诊断、出方案 | Audit | 只读产品源码；报告问题或写自包含计划 |
| 组件、表单、主题、registry | Compose | 现有组件优先，必要时用项目 CLI/registry |

目标或范围不清时，只问一个问题：改哪个路由/组件，或需要「设计、优化、审计、组件」中的哪一种。

## 所有实现模式的工作流

1. 锁定路由、组件和成功标准；从渲染入口追到实际组件、token、变体和样式。
2. 复用当前 token、字体、组件与 [DESIGN_LANGUAGE.md](DESIGN_LANGUAGE.md)；先检查现有实现，再决定是否新增。
3. 实施最小充分改动。交互组件必须使用现有可访问 primitives，不手写键盘或焦点行为。
4. 验证：相关类型检查/测试；检查手机尺寸、键盘焦点、空态与错误态。涉及主题时检查浅色和深色；涉及动画时检查 `prefers-reduced-motion`。
5. 交付时说明范围、验证结果和有意保留的限制。

## Design

先在内部形成简短方案：

- 内容与受众，以及页面唯一任务；
- 4–6 个基于现有语义 token 的色彩角色，不引入无理由的第二强调色；
- 标题、正文、辅助信息的字体与层级；上游要求的命名 HEX 与字体角色只用于概念映射，最终必须落到既有 token 与项目字体；
- 一句布局概念和一个服务内容的签名元素；
- 删除一切不能提升理解、导航或阅读的装饰。

前台可大胆但只能有一个重点；不要默认使用奶油底+陶土、酸绿黑底、报纸密栏、紫色/多色渐变、glow 或营销 dashboard。动画只在用户明确要求或确实帮助理解时加入，且只动画 `transform`/`opacity`，交互反馈不超过 200ms。

## Optimize

- 框架默认值仅可补足项目未定义的通用尺度；颜色、字体、主题与品牌阴影必须优先复用项目 token，不得回退为框架的默认品牌表达。
- 优先修复信息层级、间距节奏、行宽、对齐、空态和视觉噪声。
- 标题使用 `text-balance`，段落使用 `text-pretty`，数据使用 `tabular-nums`；密集内容可用 `truncate` 或 `line-clamp`。
- 不随意增加 `tracking-*`、渐变、阴影、任意 z-index 或全屏动效。
- 使用 `h-dvh`，固定元素考虑安全区；正方形使用 `size-*`；class 条件使用项目的 `cn`（或等价）。
- 图标按钮必须有可访问名称；破坏性操作使用确认对话框；错误显示在触发动作附近。

## Audit

- 严格只读产品源码，不安装依赖、不运行会写入的命令、不改产品文档。
- 从一个连贯表面和其真实运行路径开始，不以全仓字符串搜索推断问题。
- 每个发现都必须有：设计契约或同一任务内的直接矛盾、到达该表面的运行证据、唯一确定的修正；不满足则丢弃。
- 最多报告 3 条，按置信度、影响、覆盖面和成本排序。用户选择后才写自包含计划；Audit 本身不实现。
- 可访问性、HTML/ARIA 和功能性问题不因全局底线自动扩大 Audit 范围；仅在用户明确要求，或当前表面已有明确设计契约时报告。

## Compose

- 先检查已安装的组件；按项目既有别名、base、图标库、样式体系和包管理器工作。
- 有内置变体则不用自定义样式；颜色使用语义 token，不写原始色值或手工 dark 覆盖。
- 用 `flex` + `gap-*`，不用 `space-x/y-*` 叠间距；不要覆盖组件本身的颜色或字体。
- 表单优先项目字段原语；未安装时竖叠 Label+控件必须统一字段叠放间距，禁止散落更紧的私有 gap。空态、提示、分隔、骨架、徽标等优先使用既有组件。
- 同一交互表面只使用一种 primitive 系统（Base UI / Radix / React Aria 等），不混用。
- Card、dashboard/stat-card 或 block 组合不能作为阅读面、首页列表、归档与文章页的默认信息架构；它们只适合明确独立操作或后台工具区。
- preset 只能提供组件结构或 token 起点；应用前确认不替换字体、强调色、成对主题 token 与前台排版；状态语义色不等于第二品牌强调色。
- 动画只有确实帮助理解且验证 `prefers-reduced-motion` 时才启用；组件可用不代表默认加入动效。

## 反模式与验收

- 不违反 [DESIGN_LANGUAGE.md](DESIGN_LANGUAGE.md) 中的纸墨编辑感、单一强调色、分段壳层、操作语法、身份与互跳、表格/分页/空态规则。
- 不把后台改成品牌营销页或全屏 hero；允许壳层结构同构，禁止营销化与卡片堆砌阅读面。
- 不把前台主列表改成卡片网格。
- 不以「图标+文字」并排或实心 Button 堆叠作为壳层工具、列表新建、行内次要操作的默认形态。
- 弹窗 footer 不用实心/描边 Button、分割线或底色；按钮一律文字链（危险操作警示色）；弹窗文案不写操作教学、不加「（可选）」后缀。
- 未经用户请求，不引入紫色/多色渐变、glow、散乱动效或新的强调色。
- 审计不直接修改产品源码；执行计划时重新选择 Design、Optimize 或 Compose。
- 改主题/token 时必须同时检查浅色与深色；改前台时以「移除站点标题后，首屏仍不应像未打磨的框架脚手架」为验收标准。
- 改壳层/操作区时核对：密度同行、页底 brand、导航居中+工具靠右、导航不吸顶、Tooltip/`aria-label`、用户图标身份入口、权限互跳、登出不在壳层、文章壳/通用壳归类正确、表格边框与填满。

## 完成检查

- [ ] 模式与改动面明确，且改动未超范围
- [ ] 符合 [DESIGN_LANGUAGE.md](DESIGN_LANGUAGE.md)：纸墨编辑感、单一强调色、字体、壳层密度、操作语法、身份互跳、文章壳/通用壳、表格/分页/空态
- [ ] 后台未营销化；结构同构时仍保持工具属性
- [ ] 复用 token 和既有 primitives；没有混用交互基础库
- [ ] 浅/深色、手机、焦点、空态/错误态、Tooltip 按适用范围检查
- [ ] 同一动作的图标与文字只保留一种表达，未并排双写
- [ ] 图标动作均有 hover/focus 文字提示；Tooltip 挂外层包装，不与 Button/Link merge
- [ ] 同行控件高度一致
- [ ] 操作/导航文字链字号走 small/normal/large（默认 normal）
- [ ] 竖叠 Label+控件使用统一字段叠放间距
- [ ] 动画、性能和可访问性底线符合本文件
- [ ] 已运行最相关的验证，或说明无法运行的原因
