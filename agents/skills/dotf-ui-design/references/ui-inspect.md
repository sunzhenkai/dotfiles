# ui-inspect：现有页空间与对齐细节

本文件是 `dotf-ui-design` 的自有 phase，不是能力 skill。进入本 phase 后按下面执行。

默认模式**不另起视觉语言**。优雅重构是可选模式，见文末；未点名时不要走 4 阶段。

## 何时进入

- 用户要检查、打磨、过一遍现有页的间距、分割线、内容块 padding、图标/按钮位置、整体布局。
- 用户明确要求对**现有页**做优雅重构、换气质、赋予呼吸感。
- 整页新建或翻新：实现之后、`webapp-testing` 验收之前（默认走空间检查；用户点了优雅重构再开可选模式）。

不要用来：给新页面定视觉身份、建 token、加组件、只改一个 class、功能回归。新方向走 `frontend-design`。

## 流程

1. **定范围**：当前可见面默认必查。用户点了多页就都查；否则不擅自扩到整站。有交互态（empty / error / 展开）且同屏能到的，带上。
2. **取证**：优先看渲染结果。需要真页面时串行加载 `webapp-testing`，拍桌面宽度；布局响应式再拍一个窄屏（约 375–390px），用完即弃。没有浏览器就读结构与间距 class，并在输出里标明「证据不完整」。
3. **对照清单**：按下列块走一遍，只记真实问题。跟项目间距刻度；没有则 4px 基数。对齐到**本页已占优的节奏**，不要为这一页发明新刻度。
4. **分级记录**：P0 重叠/溢出/挡住内容；P1 同一表面节奏不一致（混用 gap、分割线一侧贴死、同级卡片 padding 不齐、按钮组不对齐）；P2 光学微调（约 1–2px）。
5. **修复**：先 P0 再 P1。改实现需要 Tailwind 模式时串行加载 `tailwind-css-patterns`，用完即弃。默认模式不顺手改配色、字号、组件库或无关页面。
6. **复检**：改过的面再看一次（有截图再截一次）。P2 未修要列出并说明为何留下。
7. **可选**：用户点了优雅重构时，在清单之后走「优雅重构」4 阶段；未点名则停在本流程。

## 清单

### 整体布局

- 内容最大宽度与水平居中与邻近页一致；不要半页贴左、半页突然撑满。
- 区块之间的垂直间距走同一台阶，不要 12/14/20 混用却无理由。
- 顶栏/侧栏/主列对齐；`sticky`/`fixed` 不挡住正文。
- 主列不要一头挤、一头大片空白（除非是有意的 hero）。

### 内容块 padding

- 同级卡片/面板/列表容器用同一 padding token。
- 外 gap 与内 padding 不要叠成「双倍空白」，也不要双双为 0 贴死。
- 嵌套容器检查 padding + gap + 子项 margin 是否叠余量。
- 最后一项多余 margin 造成底边内边距一边厚一边薄。

### 元素间隔

- 兄弟节点优先一个 `gap-*`（或等价），少用互相打架的 `mt`/`mb`。
- 紧配对（label–value、icon–text、title–subtitle）明显小于区块间距。
- 列表/栈各项间隔均匀；破例要说得出理由。
- 表单：label 到控件紧，字段与字段松一档。

### 分割线

- 线两侧空白对称，或一侧刻意贴边（例如卡片全宽分隔）；常见病是 `my-0` 加相邻 margin，一侧贴死。
- 分割线不要既画 `border` 又叠一条 `hr`，变成双线。
- 粗细/颜色跟本页已有分隔语言走，不新开一套。

### 图标与按钮

- 图标在点击区域内光学居中，不被行高顶偏。
- 图标与文字的 gap 全页一致，不要有的 `gap-1` 有的靠 padding 硬撑。
- 按钮组：同高、齐边；主/次按钮顺序与已有页一致。
- 纯图标按钮尺寸与内边距一致，并与旁边文字按钮对齐。
- 行尾操作（编辑/更多）各行落在同一垂直线；图标不挤进文字、不溢出圆角。

### 对齐

- 同一行的文字与图标共享视觉基线。
- 列表里的数字、状态、操作能看成列，不要每行各偏一截。
- 表单多行时 label / 控件起始边对齐。

### 呼吸、降噪、微交互

默认检查也看这三项，但只修明显问题，不借机换肤。

- **呼吸感**：标题/正文 `line-height` 与段间距能读完；信息不要挤成一块板。
- **降噪**：能靠背景层级分开的区域，不要再叠硬边框和重阴影。
- **微交互**：已有 hover/focus 用短 `transition`（约 150–200ms）；不主动加弹跳、视差、光影跟随，除非用户要。

## 输出（默认）

```text
scope: <页面或组件 / 状态>
viewport: <宽度；无浏览器则 source-only>
evidence: screenshot | source-only（不完整）
mode: inspect
findings:
  - P<n> <位置> — <现状> → <应对齐的 token 或规则>
actions: <已改项，或 none>
recheck: pass | fail | partial
```

对话里按 P0 → Pn 给总结，不要只报「看起来还行」。没有问题就写 `findings: none` 并说明看过哪些面。

## 优雅重构（可选模式）

仅当用户明确说优雅重构、换气质、赋予呼吸感、Web Elegance 时进入。先做完上面的空间清单，再按 4 阶段输出。目标是让现有页更有留白与层次，不是修功能 bug，也不是给新产品定视觉身份。

### 阶段一 · 听诊

列出当前页最伤节奏/可读性的 **3** 个问题（例如密度窒息、缺视觉重心、对比过刺或过灰、中西文混排发糊）。每条点到具体 class 或 CSS 属性，不要空泛「不好看」。

### 阶段二 · 处方

默认在**现有 token / 字体 / 组件**里开方：留白台阶、层级、降噪、行高。不要输出新 Hex 色板或新字体组合。

只有用户明确允许换视觉语言时：

- 按页面类型（博客 / 后台 / 文档 / 作品集等）给 **1** 个具名风格，名词要具体，例如「瑞士极简（网格 + 留白）」，不要「现代感」。
- 可附一套色值与中西文字体配对，并说明会动哪些 token。整站换肤先征得同意，必要时串行加载 `frontend-design`，用完即弃。
- 禁止用蓝紫渐变 + 通用 Inter + 大圆角毛玻璃当默认套餐。

### 阶段三 · 手术

在项目栈里改（Tailwind 或已有 CSS），不要另贴一份零侵入失败的整页 CSS。必须包含：

- **呼吸感**：重做 padding / margin / `line-height`，跟项目刻度。
- **微交互**：已有可点目标加细腻 `transition`（悬停色/位移要克制）。禁止弹跳、视差、追逐光影，除非用户明确要求。
- **降噪**：能删的边框和硬阴影删掉，用背景层级分区。

保持功能与选择器语义；响应式不断、对比度 ≥ 4.5:1。不引入大型第三方字体库或图标库；优先项目已有字体或系统回退。

### 阶段四 · 点睛

额外给 **1** 条具体、可执行的收尾技巧（例如「顶栏去底色，只留 1px 底边」）。不要强制写诗意金句。

### 本模式输出

```text
scope / viewport / evidence
mode: elegance
inspect: <空间清单 P0–Pn 摘要，或 none>
diagnosis: <3 条，含具体属性>
prescription: <token 内处方；若允许换肤则写具名风格>
actions: <已改项>
finishing-touch: <1 条技巧>
recheck: pass | fail | partial
```

### 禁忌

- 不要 AI 模板套餐（蓝紫渐变、万能 Inter、大圆角毛玻璃堆在一起）。
- 不要花哨但不服务于阅读/操作的动画。
- 不要为气质牺牲性能或可达性。
- 不要在用户没允许时换色、换字、换组件库。
