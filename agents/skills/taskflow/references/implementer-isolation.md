# 实现者输入模式

实现者输入分两种：正常交付与盲测复跑。默认是正常交付；盲测复跑必须由任务显式标记为 benchmark / regression，不得把普通交付默认盲派。

## 正常交付

目标：让实现者有足够上下文满足已确认的质量约束。

实现者必须收到：

- 需求原文与本人负责范围的边界。
- 质量画像原文，或按子 change 裁剪后仍保留语义的相关部分。
- 该范围的验收要求：页面或状态、并发与数据假设、错误边界、测试与启动证据。
- 运行约束：工作目录、依赖边界、时间预算、不得提交 / 不得外发。
- 必要的既有契约或构建方式。

实现者不必须收到：

- 完整评分 rubric 与其它子 change 的验收细节。
- 跨角色审阅意见全文。
- 与本人范围无关的历史失败细节。

审阅者仍按 [acceptance-rubric.md](acceptance-rubric.md) 独立评分；实现者自评只作输入。

## 盲测 / 基准复跑

目标：衡量流程或 agent 在未被提示时的理解与实现能力。仅当任务显式标记 benchmark / regression 时使用。

实现者只收到：

- 样例或需求原文，保持原样，不改写、不补充期望。
- 工作目录、允许写入范围与不得提交 / 不得外发约束。
- 运行约束：语言与依赖边界、本地启动要求、时间预算。
- 交付要求：可运行、有测试、有说明、留证据。

实现者不收到：

- 质量画像、角色底线清单。
- 验收 rubric、评分维度与通过线。
- 期望页面清单、功能清单或「必须包含」的隐藏清单。
- 审阅者具体意见与历史失败细节。

复跑规则：

1. 记录本次派发的原文与运行约束，作为可复现输入。
2. 审阅者持有画像与 rubric，不与实现者共享。
3. 复跑使用同一份原文，不追加事后提示；否则结果不可比。
4. 盲测结果只评价当次能力，不改变该任务已确认的质量画像与降级表。

## 派发检查

- 普通交付发现实现者没有画像或相关验收要求：先补上下文，不继续盲派。
- 盲测未显式标记 benchmark / regression：按普通交付补上下文。
- 需要实现者知道的期望没有写进画像或验收要求：先补上游文档，不靠私聊提示词传递。
- 多实现者并行时，正常交付按子范围裁剪上下文；盲测复跑使用同一原文。

## 边界

- 隔离是受控评测手段，不是默认交付策略。
- 盲测不降低验收：画像与 rubric 仍生效，只是由审阅者持有。
- 正常交付不得把完整仓库无关上下文全部塞给实现者；按负责范围裁剪，但不得丢失质量语义。
