# PREVIEW 模式

只读观察：把页面跑起来、截图、看 console/network，**不改任何代码**。用户问「看看现在什么样」「先预览一下」「截个图看看」或想先确认效果再决定是否修改时使用。

## 流程

1. **定位启动方式**：先看 `package.json` scripts、`Makefile`、`docker-compose.yml`、项目 README；静态 HTML 直接用浏览器打开。已在跑的服务直接复用，不要重复起。
2. **起服务**：按项目惯例启动（如 `npm run dev`），等待就绪；记录访问 URL 与端口。后台运行并记住进程，收尾时停掉。
3. **截图与检查**：用 Playwright 或可用的浏览器工具：
   - 截图 375x812、768x1024、1440x900；
   - 检查横向滚动、长文本/中英混排溢出；
   - 收集 console error 与 network error；
   - 快速过一遍 Tab 顺序与 focus-visible 可见性。
4. **输出观察报告**：

```md
## PREVIEW
- 环境：<启动方式与 URL>
- 断点截图：<路径或已确认>
- console：<干净 / 列出新 error>
- network：<干净 / 列出新 error>
- 观察到的问题：
  1. <现象> @ <位置/断点>（P0/P1/P2）
- 建议：进入 build 修复 / 仅记录
```

5. **收尾**：停掉自己起的进程（进程组优先，不误杀已存在的服务）；临时截图放临时目录，不进仓库。

## 边界

- 发现问题只汇报，不擅自进入 build 修复；由用户决定下一步。
- 无法截图时说明原因，并给出人工检查步骤（打开哪个 URL、看哪些断点）。
- preview 不替代 GATE：它只看运行态现象，不做改动正确性断言。
